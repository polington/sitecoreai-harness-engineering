## Title

Promo Card Grid

---

## Feature Overview

The Promo Card Grid provides content authors with a reusable, responsive grid of promotional cards placed in the `headless-main` placeholder. A container component references one or more Promo Card data source items via a multi-value field, and each card presents an authored image, title, description, and optional call-to-action link. This enables marketing teams to assemble and maintain collections of promotional content without developer involvement.

---

## Design Intent

- **Content-forward presentation** — the grid should showcase authored imagery and copy without competing visual decoration, consistent with the design system's content-first principle.
- **Visual consistency** — all cards within the grid share identical structure and proportions, reinforcing the calm, professional aesthetic. Equal card heights prevent jagged row edges.
- **Reuse over novelty** — the card pattern and grid layout draw from established design-system primitives (spacing tokens, typography scale, responsive breakpoints) rather than introducing new visual systems.
- **Author flexibility** — the component gracefully handles varying card counts (including zero) and optional fields, so authors never encounter layout breakage.
- **Accessibility as baseline** — semantic markup, meaningful alt text, visible focus states, and keyboard reach are built-in expectations rather than enhancements.

## Page / Feature Structure

The Promo Card Grid is a standalone section placed within the `headless-main` placeholder. Its structural hierarchy is:

- **Grid Section** — an outer semantic wrapper providing vertical spacing consistent with adjacent page sections.
  - **Grid Container** — a constrained-width, centered container that holds the responsive CSS grid.
    - **Card (×n)** — each referenced Promo Card item is rendered as a discrete visual unit within the grid.

When no cards are referenced, the component renders nothing visible — no empty wrapper markup is output.

---

## Section Breakdown

### Grid Section

- **Purpose:** Establishes the vertical position and spacing of the grid relative to surrounding page content.
- **Expected content:** A single grid container.
- **Visual guidance:** Standard section spacing (design system `space-y-10` to `space-y-16` equivalent) above and below. No background fill or border — spacing alone separates it from adjacent sections.

### Grid Container

- **Purpose:** Constrains the grid to the page content width and applies the responsive column layout.
- **Expected content:** One or more Promo Card components arranged via CSS Grid.
- **Visual guidance:** Gap between cards uses design-system spacing tokens (recommended `gap-6` / 24px at desktop, `gap-4` / 16px at mobile). Content-width centering with horizontal padding consistent with the site container pattern.
- **Interaction:** No direct interaction; the container is purely structural.

### Promo Card

- **Purpose:** Presents a single promotional item as a cohesive visual unit within the grid.
- **Expected content (top to bottom):**
  1. **Image** — displayed at the top of the card with a consistent aspect ratio (16:9 recommended). Uses Next.js Image optimisation. Alt text is authored.
  2. **Title** — rendered as a heading element (h3 recommended within the page heading hierarchy). Uses the design-system heading scale (H3: 24–28px).
  3. **Description** — body text below the title. Uses the standard body text size (16–18px) with generous line height.
  4. **CTA Link** — a text link or minimal button styled as a call-to-action. Only rendered when the link field is populated.
- **Visual guidance:** Card background uses a neutral surface colour (white or near-white in light mode). Subtle border or very light shadow to delineate the card boundary without heavy decoration. Internal padding using design-system spacing tokens (16–24px). Equal height enforced across the row via CSS Grid alignment.
- **Interaction:** The CTA link is the only interactive element. It receives a visible hover state (underline or subtle colour shift) and a clear focus indicator. The card itself is not a click target — only the explicit CTA is interactive.

## Component Recommendations

- **Grid layout primitive** — use CSS Grid (via Tailwind utility classes) for the responsive column layout. This is already the established layout approach in the headapp.
- **Image rendering** — use the Next.js `<Image>` component with the Sitecore Image field value for optimised loading, lazy loading, and responsive sizing.
- **Link rendering** — use the existing Sitecore link field helper/component pattern already present in the headapp for General Link fields.
- **Card component** — a focused, single-purpose presentational component. No abstraction beyond what is needed for this feature.
- **Section/Container wrapper** — reuse existing container/section patterns from the headapp layout system for consistent max-width and padding.

## Responsive Behaviour

### Mobile (< tablet breakpoint)

- Grid renders as a single column (1-up).
- Cards stack vertically with consistent vertical gap (16px recommended).
- Card images span the full card width; aspect ratio is preserved.
- Typography remains at standard body and heading sizes — no reduction needed.
- CTA links remain full-size touch targets.

### Tablet (tablet to desktop breakpoint)

- Grid renders as two columns (2-up).
- Gap between columns and rows at 24px.
- Cards maintain equal height within each row.
- Content width remains constrained within the site container.

### Desktop (≥ desktop breakpoint)

- Grid renders as three columns (3-up).
- Gap between columns and rows at 24px.
- Cards maintain equal height within each row.
- Container width follows the site's max-width constraint to preserve readable content width and avoid excessive stretching.

### Cross-breakpoint rules

- No horizontal overflow at any breakpoint.
- Heading hierarchy remains consistent regardless of column count.
- Image aspect ratio stays fixed (16:9) across all breakpoints — cropping via `object-cover`.
- The grid degrades gracefully for any card count; a single card at desktop still aligns to the left column rather than stretching full-width.

## Accessibility Considerations

- **Semantic structure:** The grid should use a `<ul>` / `<li>` list structure (or equivalent ARIA `role="list"` / `role="listitem"`) so assistive technologies announce the collection and item count.
- **Heading hierarchy:** Card titles use `<h3>` (or the appropriate next level below the page section heading) to maintain a logical heading tree.
- **Image alt text:** Each card image uses the authored alt text from the Sitecore Image field. Authors are responsible for providing meaningful descriptions; the component must not suppress or override the alt value.
- **Keyboard accessibility:** CTA links are focusable in document order. No keyboard trap exists within the grid.
- **Focus indicators:** CTA links display a visible focus ring that meets WCAG 2.1 minimum contrast requirements.
- **Colour contrast:** Card text (title, description, CTA) against the card background must meet WCAG AA contrast ratio (4.5:1 for body text, 3:1 for large text).
- **Empty state:** When zero cards are referenced, no empty landmark or list is rendered — assistive technologies encounter no confusing empty structure.
