## Technical Approach

The Carousel is a client component — it requires interactive state for panel tracking, autoplay timers, hover and keyboard event handling, and document-visibility management. The top-level `Carousel.tsx` carries `'use client'` and manages all reactive state. Static sub-components (panel, controls, indicators) are defined as plain React functions within the same folder and remain free of their own `'use client'` declarations.

Panel content follows the same multi-item pattern already used by `PromoCardGrid` — a `fields.Panels` array where each item has a stable `id` and a `fields` bag. Panel fields are typed in `carouselTypes.ts` following the `teaserTypes.ts` naming convention. Each panel exposes `Title` (optional), `Image`, `Description`, and `Link` fields — this mirrors the slide-variant teaser fields that already exist in the project, avoiding a novel content model.

The `Image` primitive from `@sitecore-content-sdk/nextjs` is used for all panel images, with `object-cover` and `object-center` Tailwind classes for cover cropping. Variant-specific layout (default / hero / mini) is resolved from a `VARIANT_CLASSES` lookup map keyed on the authored `Variant` field — the same pattern used by `Teaser.tsx`.

All interactive behavior (active panel index, playback state, pause source) is managed through `useState` and `useEffect` hooks inline in `Carousel.tsx`. No separate hook file is introduced. The autoplay timer uses `useRef` to hold the interval ID and is cleared on cleanup. The Page Visibility API (`document.addEventListener('visibilitychange', ...)`) drives the document-hidden pause. A `pauseSource` enum distinguishes `'user'`, `'hover'`, `'hidden'`, and `'none'` so that a user-initiated pause cannot be overridden by hover or visibility events.

Component map naming follows the project rules confirmed in `sitecore.cli.config.ts` (scan path `src/components`, exclusions `content-sdk/*` and `**/__tests__/*`):

- `Carousel.tsx` — PascalCase, registers as `Carousel` in the component map (intended)
- `carouselTypes.ts` — camelCase prefix, registers as `carouselTypes` (harmless, no Sitecore rendering item)
- `carouselPanel.tsx` — camelCase, registers as `carouselPanel` (harmless)
- `carouselControls.tsx` — camelCase, registers as `carouselControls` (harmless)
- `carouselIndicators.tsx` — camelCase, registers as `carouselIndicators` (harmless)
- No barrel `index.ts`

After adding these files, `sitecore-tools:generate-map` must be run to regenerate `.sitecore/component-map.ts` and related import-map files.

### Slice 3 — Autoplay, pause-on-hover, user pause/resume, and document-hidden pause

**Purpose:**  
Introduce the full playback state machine. Autoplay is disabled by default. When enabled, panels advance after the configured delay. Hover pauses advancement (when `PauseOnHover` is enabled). Explicit user pause/resume is sticky — not overridden by hover or visibility events. Document-hidden pause uses the Page Visibility API.

**Likely areas affected:**
- `src/components/Carousel/Carousel.tsx` (add `pauseSource` state, `useEffect` for timer and visibility listener)
- `src/components/Carousel/carouselControls.tsx` (play/pause button, visible only when autoplay is configured)

**Validation focus:**
- Autoplay off by default; enabled when `Autoplay` field is true
- Timer advances panels at the configured `TransitionDelay` (default 5 s)
- Hover pauses when `PauseOnHover` is enabled; hover-leave resumes (unless user-paused)
- User pause is not cleared by hover, hover-leave, or visibility change
- `document.visibilityState === 'hidden'` pauses advancement; returning to visible restores the prior play/pause state
- Timer cleanup: interval is cleared when the component unmounts

## Risks

- **Autoplay interval and React strict mode:** In development, React Strict Mode double-invokes effects. The interval `useEffect` must use the cleanup return to clear the interval to avoid double-advancing in development. Use `useRef` for the interval ID.
- **Page Visibility API in test environment:** `document.visibilityState` and `visibilitychange` events are available in jsdom but may need explicit simulation. Use `Object.defineProperty(document, 'visibilityState', ...)` and `document.dispatchEvent(new Event('visibilitychange'))` in tests.
- **Hero variant full-bleed breakout:** The hero variant's edge-to-edge presentation requires overriding any containing layout padding. This may need a negative-margin technique (`-mx-4 sm:-mx-6 lg:-mx-8` or similar) if the home-page layout uses a constrained container. The exact override depends on the layout structure around `headless-main` and must be confirmed during build.
- **Focus management during transition:** When the cross-fade transition changes panel visibility (opacity / display), if a currently focused element is inside the outgoing panel, focus may be lost or moved. The implementation must test this and ensure `aria-hidden="true"` is only applied after any focused element has been removed from the outgoing panel.
- **Component map bloat:** The five Carousel source files will each produce a harmless entry in `.sitecore/component-map.ts`. This is expected behavior per the project standard and does not require remediation.
