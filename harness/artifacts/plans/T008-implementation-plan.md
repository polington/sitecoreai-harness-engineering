## Technical Approach

The Accordion is a client-side interactive component registered in the Sitecore component map as a **client component**. It requires React `useState` to track the currently open item, which makes `'use client'` mandatory on the root component.

The component follows the same structural conventions as the existing Carousel: a PascalCase root file (`Accordion.tsx`) handles state and layout; camelCase sub-components handle rendering concerns; a camelCase types file holds all TypeScript interfaces. No barrel `index.ts` is created.

**Component map scan path** (`sitecore.cli.config.ts`): `src/components`, excluding `src/components/content-sdk/*` and `src/components/**/__tests__/*`. All files in `src/components/Accordion/` will be picked up unless they fall under `__tests__/`. Sub-component and types file names must be camelCase to avoid unintended Sitecore component map entries.

**State model**: `useState<string | null>` tracks the ID of the currently open item. `null` means nothing is open. On mount, the initial value is derived from the `InitiallyExpandedItem` field: if the referenced ID exists in the items array, that item opens; otherwise null.

**Single-expansion rule**: toggling a header sets the open ID to that item's ID if it is currently closed, or to `null` if it is already open. Opening any item implicitly closes the previously open one because only one ID is tracked.

**Heading level**: the `HeadingLevel` field value (`'h2'`/`'h3'`/`'h4'`) is used as a dynamic JSX tag. The visual scale is always H4-equivalent (Tailwind typography classes); the semantic element varies per the author's choice. An invalid or absent value defaults to `'h3'`.

**Item count**: the component renders items in the order received. Enforcement of the 10-item maximum is an authoring concern (Sitecore insert options); the component defensively renders only the first 10 items if the array exceeds that count.

**WKND styling**: implemented with Tailwind utility classes following existing component conventions. No custom CSS files; no ad-hoc spacing values. Full-width rows, thin `border-b` dividers, bold uppercase text, right-aligned ±icon, indented body with `aria-hidden`-safe transition.

**Panel visibility**: collapsed panels use the HTML `hidden` attribute (removes from accessibility tree and layout). The reveal transition is a CSS-based fade/height effect applied when the item becomes active.

## Risks

- **Tailwind transition with `hidden` attribute**: CSS transitions do not fire when `hidden` is toggled because the element is removed from layout immediately. The implementation plan should use a height/opacity technique that adds `hidden` only after the transition completes, or relies on CSS `grid-template-rows` animation — the Build agent should validate this approach against the existing codebase's transition patterns.
- **`import-map.client.ts` is auto-generated**: The file comment reads "auto-generated by the Sitecore Content SDK." The Build agent must confirm the correct workflow: whether to edit it directly (as appears to be the current practice, based on the Carousel entries being present) or regenerate it. Based on the current state of the file, direct editing following the established pattern is the expected approach.
- **Heading level as dynamic tag**: React requires dynamic HTML tag names to be assigned to a capitalized variable (`const Tag = headingLevel`). The Build agent must follow this pattern to avoid React rendering issues.
- **Item count enforcement**: The 10-item limit is enforced by Sitecore insert options, not the component. A defensive slice (`.slice(0, 10)`) in the component is low-risk insurance but is not strictly required by the spec; the Build agent can include it.
