## Design Alignment Review

### Structural Alignment

The implementation closely follows the design note's layered visual structure:

- **Three-layer composition**: Background image → overlay scrim → text content region.
  This matches the design note's ASCII diagram exactly. The background image is
  absolute-positioned within the container. The scrim overlay sits on top of the image
  (also absolute-positioned). The text content region carries `relative z-10` to sit
  above the scrim. Layering order is correct.
- **Single component, no sub-components**: The design note explicitly recommends no
  sub-components. `HeroBanner.tsx` is the sole rendering file, consistent with this
  recommendation. The heading, subheading, and CTA are rendered inline within the
  component.
- **Full-width breakout**: The negative-margin viewport-width technique
  (`relative left-1/2 right-1/2 -ml-[50vw] -mr-[50vw] w-screen`) matches the
  implementation plan's specified approach and achieves the design note's intent of
  edge-to-edge rendering.
- **No additional landmarks**: The component renders a `<div>` as its outermost
  element, not a `<section>` or landmark region. This is correct — the hero banner is a
  content component within the existing `<main>` region provided by `Layout.tsx`, not a
  page-level structural element. Consistent with the design note.

### Visual / System Alignment

- **Typography**: Heading uses `text-3xl lg:text-5xl font-bold text-white` (30px → 48px,
  bold, white). The design note specifies H1 scale 36–48px on desktop, bold or semi-bold,
  white or high-contrast light colour. Desktop value (48px) matches perfectly. Mobile
  value (30px) falls within the design note's mobile range (28–32px). ✅
- **Subheading**: `text-lg lg:text-xl text-white` (18px → 20px, white). The design note
  specifies body or large body scale 18–24px, visually subordinate to the heading.
  Values are within range and subordinate. ✅
- **Spacing**: `mt-4` (16px) between heading and subheading (design note: 16–24px). `mt-6`
  (24px) between subheading and CTA (design note: 24–32px). Both within specified ranges.
  All spacing values are from the design system's spacing scale (4, 8, 16, 24, 32, 48, 64). ✅
- **CTA button style**: White background (`bg-white`), dark text (`text-neutral-900`),
  rounded corners, medium font weight. This matches the design note's "light/white button
  with dark text" recommendation. Hover state `hover:bg-neutral-100` provides subtle
  visual change consistent with the design system's interaction model. ✅
- **Overlay scrim**: Flat `bg-black` at configurable opacity. No gradients, patterns, or
  directional fades. Matches the design note's "visually smooth and uniform" direction. ✅
- **No decorative excess**: No shadows, gradients, or unnecessary visual elements. The
  design system's visual restraint principle is maintained. ✅

### Responsive Behaviour

- **Mobile**: Full-width and `60vh` height preserved. Heading scales down (30px). Subheading
  remains at 18px. Horizontal padding (`px-6` = 24px) prevents text overflow. Text wraps
  naturally within the `max-w-4xl` constraint. ✅
- **Desktop**: Heading at 48px, subheading at 20px, increased padding (`lg:px-8` = 32px).
  Content width constrained by `max-w-4xl` to prevent excessively long lines. ✅
- **Cross-breakpoint**: The `lg` breakpoint is consistent with the Header and SiteFooter
  components' responsive breakpoint (`lg` = 1024px). The hero banner's layered structure
  (image → scrim → text) remains consistent at all breakpoints. ✅

### Accessibility Expectations

- **Heading structure**: `<h1>` for the heading, `<p>` for the subheading. Preserves
  heading hierarchy for subsequent page content. Matches design note. ✅
- **Alt text**: Sourced from Sitecore Image field. Empty alt produces `alt=""` (decorative
  treatment). Matches design note's author-controlled approach. ✅
- **Keyboard accessibility**: CTA is a native `<a>` element, keyboard-focusable via Tab,
  activatable via Enter. No other interactive elements require keyboard interaction. ✅
- **Visible focus state**: `focus:ring-2 focus:ring-white focus:ring-offset-2 focus:ring-offset-black`
  produces a white focus ring with dark offset, visible against the dark scrim. Consistent
  with the design note's requirement for a light-coloured focus ring visible on dark
  backgrounds. ✅
- **No motion or animation**: The hero is static — no auto-play, transitions, or flashing
  content. Satisfies WCAG 2.3.1. ✅
- **No ARIA needed**: The design note confirms no landmark roles or additional ARIA
  attributes are required. The semantic HTML elements (`<h1>`, `<p>`, `<a>`, `<img>`)
  are sufficient. The implementation does not add unnecessary ARIA. ✅

### Component / Pattern Alignment

The file naming convention follows the established project patterns:
- `HeroBanner.tsx` — PascalCase, registered in the component map as `HeroBanner`.
- `heroBannerTypes.ts` — camelCase, avoids unintended component map registration (same

- `__tests__/HeroBanner.test.tsx` — excluded from component map by the `__tests__`
