## Issues Identified

### Issue 1 — Keyboard Focus Reaches Interactive Content in Collapsed Panels

**Description:** The implementation uses `aria-hidden={!isOpen}` to hide collapsed panels from the accessibility tree. However, `aria-hidden="true"` does not remove elements from the keyboard tab order. Any interactive elements inside a collapsed panel (e.g., anchor links rendered by `RichText`) remain focusable via Tab even though the panel is visually hidden (zero height, `grid-rows-[0fr]`) and removed from the screen reader tree. This means keyboard users can Tab into invisible content — a recognized WCAG 2.1 failure pattern (SC 2.1.1 and 2.4.3). The design note specifies that "collapsed panels must be removed from the accessibility tree and normal tab order."

Recommended fix: Add the `inert` attribute to the collapsed panel wrapper (`inert={!isOpen ? '' : undefined}`). The `inert` attribute prevents focus, pointer events, and find-in-page on all descendant elements and is supported in all modern browsers. This is a one-line change to `accordionItem.tsx`.

**Severity:** Medium  
**Blocks approval:** No — this is not a regression (no prior behavior to regress against) and the RichText content may not always contain focusable elements, but it is a meaningful accessibility gap that should be resolved before the feature is used with rich panel content.

**Description:** The item title uses `text-lg` (18px in Tailwind's default scale). The design note specifies "approximately H4 scale (~20–22 px per design system heading scale)," and the design system lists H4 at 20–22px. `text-xl` (20px) would align with the lower bound of the target range. This is a cosmetic deviation; the visual hierarchy is still clear at 18px, but it does not match the specified scale.

Recommended fix: Change `text-lg` to `text-xl` in `accordionItem.tsx` line 25.

**Severity:** Low
