## Design Alignment Review

**Structural alignment**: The implementation follows the design note's anatomy precisely — Image Region → Pretitle → Title → Description → Action Area is the render order in all non-card variants. The card variant positions the pretitle badge over the image as specified.

**Variant layout geometry**: All seven variants are implemented with `VARIANT_CLASSES` providing the layout geometry from the design note: featured split (2/3 image + 1/3 content), hero full-width stage with overlay content panel, card aspect-square with absolute image fill and bottom-aligned content, list constrained 96×96px image with flex-row layout, slide tall image with lower-left content on desktop, secure with `opacity-80` muted treatment.

**Typography and spacing**: Title uses `text-2xl font-serif font-bold` (md: `text-3xl`), matching the serif bold treatment from the design note. CTA treatment is filled uppercase (`bg-neutral-900 px-5 py-2 text-sm font-semibold uppercase tracking-wider text-white`), consistent with the design system's filled uppercase CTA pattern. Pretitle is `text-xs font-bold uppercase tracking-wider text-neutral-500`.

**Responsive behavior**: Tailwind responsive prefixes implement the design note's collapse specifications — featured uses `md:flex-row` to go side-by-side at medium breakpoints, collapsing to `flex-col` at narrow; hero uses `md:absolute md:bottom-0` for overlay positioning at desktop; slide uses `md:absolute md:bottom-8 md:left-8` for lower-left desktop placement.

**Accessibility**: Heading levels are author-configurable (H2/H3/H4). Image alt text is preserved or cleared based on decorative flag. Link labels derive from title via `aria-label`. The secure restriction cue communicates state in visible text. No hover-only interactive patterns present.

**Partial alignment — card description suppression**: The card variant suppresses the description field (`!isCard` guard on the description render). The design note specifies this behavior, so it is correctly aligned. The title is visually hidden with `sr-only` in the card variant per the design note's image-forward intent, maintaining accessibility while hiding it visually.

**No deviations identified.**
