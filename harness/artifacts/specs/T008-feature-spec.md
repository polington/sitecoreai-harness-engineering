## Title

Accordion Component

---

## Feature Goal

Deliver a reusable, accessible disclosure component that allows content authors to present titled content panels that visitors can expand and collapse. The component targets FAQ-style presentation but is general-purpose enough for any titled panel scenario. It is placed in the `headless-main` placeholder and will be demonstrated on the home page above the footer.

---

## User Value

**Visitors** can scan a list of titled questions or topics, open only the panels they care about, and navigate the content efficiently with a keyboard or assistive technology.

**Content authors** can build and manage panel collections—adding, naming, editing, reordering, and removing items—through a standard authoring interface without engineering support.

---

## In Scope

- A vertically stacked set of full-width disclosure rows rendered through the Sitecore JSS route and layout pipeline in the `headless-main` placeholder.
- Each row has a left-aligned bold uppercase title and a right-aligned plus/minus state icon.
- Clicking or activating a row header toggles the associated content panel between expanded and collapsed.
- **Single expansion** (fixed behavior): opening one panel collapses all others; at most one panel is open at any time.
- Configurable **initial expansion**: one or more panels can be pre-opened on page load; invalid item references are silently ignored.
- Configurable **heading level** for item titles, constrained to the design system's permitted range.
- Configurable **presentation variant** field (defaults to WKND base accordion style).
- Stable item identity for state management and ARIA relationships.
- Maximum of **10 items** per accordion instance; the authoring interface enforces this limit.
- **Empty state**: an accordion with no items renders an authoring empty-state placeholder and produces no visible controls in the published view.
- **Single-item state**: renders without misleading multi-item controls.
- Panel content supports nested text, images, links, lists, and other allowed content blocks; content is preserved through toggle cycles.
- Keyboard operability: all headers are reachable via Tab and activatable via Enter/Space; focus remains predictable after toggling.
- Screen-reader operability: each header exposes its expanded state and the ID of its controlled panel; each panel is hidden from reading order when collapsed.
- WKND visual treatment: full-width borderless headers with a lower divider, approximately 1 em padding, bold uppercase title at ~h4 scale, plus/minus icon on the right, indented body copy in the expanded panel, short fade-in transition.
- Responsive behavior: rows remain full width; long titles wrap without hiding the icon or reducing the tap target; panel content reflows at narrow viewport widths.
- Authored accordion placed on the home page in the `headless-main` placeholder at the bottom of the page, immediately before the footer.
- Unit and integration tests covering collapsed, expanded, hover, focus-visible, pressed/toggling, single-expansion, initial state, keyboard interaction, nested content, empty state, and heading semantics.

---

## Out of Scope

- FAQ-specific content, copy, or data—the component is content-agnostic.
- Search or filtering functionality within the accordion.
- Analytics or event tracking.
- A new rich-text editor or content authoring tool.
- Mock data, local development fallbacks, or CMS-offline workarounds.
- Custom CSS selectors, HTML attribute prescriptions, JS hook names, or repository paths beyond what the implementation plan defines.
- Animation beyond a short reveal transition (no spring physics, third-party animation libraries, or configurable duration).
- Multiple-expansion mode (configurable toggle between single and multiple expansion is not required).
- Deep linking via URL fragment (panels do not open or scroll based on URL hash).
- Accordion-to-accordion navigation shortcuts (e.g., pressing arrow keys to jump between items is not required unless provided by the design system).

## Acceptance Criteria

### Authoring

1. A content author can create an accordion component in the `headless-main` placeholder and add at least three items, each with a distinct title and panel content.
2. A content author can rename an item, edit its panel content, and see the updated values in the published view without stale or lost content.
3. A content author can reorder items; the rendered output reflects the author-defined order.
4. A content author can remove an item; the removed item no longer appears in the rendered view.

### Rendering

5. The component renders through the existing Sitecore JSS route and layout pipeline—it is registered in the component map and resolved from layout service data without bypassing the composition model.
6. An accordion with zero items does not render any visible disclosure controls in the published view.
7. An accordion with one item renders that single item without misleading multi-item affordances.
8. The authoring interface prevents adding more than 10 items to a single accordion instance.

### Expand / Collapse Behavior

9. Clicking or activating a collapsed row header expands the associated panel; clicking or activating it again collapses the panel.
10. The expanded/collapsed state of the header control and its panel remain synchronized at all times.
11. Opening any row closes the previously open row; at most one row is open at any time.

### Initial State

12. Items listed as initially expanded are rendered open on first load; if multiple are listed, the first in list order opens.
13. Item references that are invalid (non-existent item IDs) in the expanded-items field are silently ignored; valid items still open correctly.

### Panel Content

14. Panel content that includes nested text, links, images, and lists renders correctly when the panel is expanded.
15. Panel content is intact when the panel is re-opened after having been collapsed.

### Accessibility

16. Each item header is reachable by keyboard (Tab) and can be toggled by Enter or Space.
17. Focus does not jump unexpectedly when a panel is opened or closed.
18. Each header control exposes `aria-expanded` (or an equivalent platform attribute) reflecting the current panel state and references its controlled panel via `aria-controls`.
19. Each panel is hidden from the accessibility tree or reading order when collapsed, using `hidden`, `aria-hidden`, or the disclosure semantics of the target environment.
20. The visual expanded state is communicated through layout and structural change, not color alone; the plus/minus icon is a secondary cue.

### Visual Treatment

21. Rows are full width within the containing column with a thin lower divider separating them; headers have no top or side borders.
22. Item titles are bold, uppercase, and rendered at approximately heading-4 scale.
23. The state icon (plus when collapsed, minus when expanded) is aligned to the far right of each header.
24. Expanded panel content is indented slightly from the header title, uses body typography, and appears directly beneath the header with a short reveal transition.
25. On a narrow (390 px) viewport, rows remain full width, long titles wrap without hiding the icon or reducing the tap target to text width, and panel content reflows naturally.

### Testing

26. Automated tests cover: collapsed, expanded, hover, focus-visible, pressed/toggling, single-expansion, initial state, keyboard interaction, nested content, empty state, and heading-level semantics.
27. All tests pass in CI before the task is considered complete.

## Dependencies

- Sitecore JSS route and layout pipeline with `headless-main` placeholder registered and active on the target site.
- Content composition capability for nested panel content (rich text or component-level nesting as supported by the delivery environment).
- Stable item identity mechanism for state management and ARIA relationships.
- Heading-level configuration from the delivery environment's permitted hierarchy.
- Disclosure interaction capability (React state, browser `<details>`, or equivalent).
- WKND design tokens (typography scale, spacing, border treatment) available to the component's stylesheet.

---

## Risks

- **Heading-level hierarchy**: Authors may configure a heading level that disrupts the page's document outline if no validation or guidance is provided.
- **Initial-state conflict**: If multiple items are listed as initially expanded, only the first in list order opens (since single-expansion is always active); the implementation plan must codify this rule.
- **Panel content richness**: Nested components inside panels increase DOM complexity and may interact unexpectedly with the accordion's visibility/accessibility logic.
- **Animation and layout shift**: A poorly implemented reveal transition can cause layout shift that breaks the visual stability criterion.
