## Title

Promo Card Grid

---

## Feature Goal

Deliver a Promo Card Grid container component and a Promo Card presentational component that together allow content authors to compose a responsive grid of promotional cards on any page using the `headless-main` placeholder. Cards are referenced via a multi-value field on the grid's data source, and each card exposes authored image, title, description, and optional link fields.

---

## User Value

Content authors need a flexible, reusable way to present collections of promotional content (offers, highlights, featured items) in a visually consistent grid layout. This component enables authors to create and maintain promo card items independently, then assemble them into grids on any page without developer assistance, reducing time-to-publish for marketing campaigns and content updates.

---

## In Scope

- **Promo Card Grid container rendering** that:
  - Exposes a multi-value field (Multilist or Treelist) referencing one or more Promo Card data source items.
  - Renders a responsive CSS grid layout: 1 column on mobile, 2 columns on tablet, 3 columns on desktop (aligned to design system breakpoints).
  - Maintains equal card heights within each row.
  - Applies design system spacing/gap tokens between cards.
  - Renders gracefully with zero referenced cards (empty state — no errors, no visible wrapper markup leaked to the page).

- **Promo Card presentational component** that:
  - Renders an authored image (Sitecore Image field) using Next.js Image optimisation with a consistent aspect ratio.
  - Renders an authored title (Sitecore Single-Line Text field) as a heading element.
  - Renders an authored description (Sitecore Multi-Line Text field) as body text below the title.
  - Renders an authored link (Sitecore General Link field) as a clickable call-to-action when the link field is populated; omits the CTA element entirely when the link field is empty.

- **Sitecore template definitions:**
  - A data source template for the Promo Card Grid containing the multi-value field referencing Promo Card items.
  - A data source template for the Promo Card containing image, title, description, and link fields.

- **Rendering registration:**
  - The Promo Card Grid is registered as an available rendering for the `headless-main` placeholder.

- **Accessibility:**
  - Semantic HTML markup (e.g. list or section structure, heading hierarchy).
  - Meaningful alt text on card images (authored via the Image field).
  - Visible focus states on interactive elements (links).
  - Appropriate ARIA attributes where semantic HTML alone is insufficient.
  - Keyboard navigability of all interactive elements.

- **Unit and component tests** covering:
  - Grid rendering with multiple cards.
  - Grid rendering with a single card.
  - Grid rendering with no cards (empty state).
  - Individual card rendering with all fields populated.
  - Individual card rendering without the optional link field.
  - Responsive column count behaviour across breakpoints.

- **CMS Configuration Guide** documenting all Sitecore items, templates, rendering definitions, placeholder settings, available renderings entries, data source configuration, and serialization steps.

---

## Out of Scope

- Nested placeholder approach for card composition (cards are referenced via a multi-value field, not inserted as child renderings).
- Carousel or slider behaviour for cards.
- Configurable column counts per instance (the grid uses a fixed responsive pattern: 1/2/3 columns).
- Card animations or hover transition effects beyond basic CSS hover states.
- Content personalisation or A/B testing on individual cards.
- Card variants or alternate card layouts (single card design only).
- Filtering or sorting of cards by category or tag.
- Pagination or "load more" for large numbers of cards.
- Mock data, local development fallback data, or CMS-offline workarounds — live CMS connectivity is assumed.

---

## Acceptance Criteria

1. The Promo Card Grid rendering is registered as an available rendering for the `headless-main` placeholder.
2. A data source template exists for the Promo Card Grid with a multi-value field (Multilist or Treelist) that references Promo Card items.
3. A data source template exists for the Promo Card with fields: image (Image), title (Single-Line Text), description (Multi-Line Text), and link (General Link).
4. When a Promo Card Grid data source references one or more Promo Card items, the grid renders each card in a responsive layout: 1 column at mobile breakpoint, 2 columns at tablet breakpoint, 3 columns at desktop breakpoint.
5. Each rendered promo card displays the authored image with appropriate alt text, a title rendered as a heading element, a description rendered as body text, and a CTA link when the link field is populated.
6. When a card's link field is empty, no CTA element is rendered for that card.
7. When the multi-value field references zero cards, the component renders without errors and does not output empty wrapper markup visible to the user.
8. Cards within a row maintain equal height regardless of content length differences.
9. Gap spacing between cards uses design system tokens.
10. All interactive elements (CTA links) receive visible focus indicators and are reachable via keyboard navigation.
11. The component uses semantic HTML and provides meaningful alt text for assistive technology users.
12. Unit/component tests pass for: multiple cards, single card, empty state, card with all fields, card without link, and responsive column behaviour.
13. The feature renders through the existing route and layout pipeline — no custom route handling or layout bypass.

---

## Dependencies

- Design system breakpoint tokens and spacing/gap tokens must be defined and available.
- Next.js Image component available in the headapp framework.
- Sitecore layout service returns multi-value field data with resolved item references (standard XM Cloud behaviour for Multilist/Treelist fields with rendering datasource resolution).
- The `headless-main` placeholder must already exist with placeholder settings that can be extended.

---

## Risks

- Multi-value field resolution: If Sitecore layout service does not fully resolve referenced item fields inline, additional GraphQL queries or field expansion may be required. This should be validated during implementation planning.
- Image aspect ratio consistency depends on authored images having similar proportions; the component enforces a consistent ratio via CSS but extreme source ratios may crop unexpectedly.
- Large card counts (e.g. 20+) are not paginated — performance and layout degradation at high counts should be noted but is explicitly out of scope.
