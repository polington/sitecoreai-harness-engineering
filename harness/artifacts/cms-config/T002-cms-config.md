## Section 1 — Create the SiteFooter Rendering and Datasource Template

> ⚠️ **Pre-execution URL check (recipe currency):**  
> Before executing this section, visit the
> [Sitecore Accelerate Cookbook recipe](https://developers.sitecore.com/learn/accelerate/xm-cloud/implementation/developer-experience/creating-new-components)
> and verify whether the steps listed here match the current published version.
> If the live recipe differs, follow the published recipe over the steps in this guide.

> **Fallback notice:** The Accelerate Cookbook recipe URL was not reachable at guide-generation
> time. The steps below use the **Clone Rendering SPE script** fallback as documented in
> the CMS Configuration Guide template. This is the prescribed fallback — not an invented
> alternative. Verify against the live recipe before executing.

The **Clone Rendering SPE script** creates both a Json Rendering item and a paired datasource
template in a single step by cloning an existing rendering. This avoids manual item creation
and ensures the rendering is wired correctly from the outset.

**Steps:**

1. Open **Content Editor**.

2. Navigate to an existing Json Rendering in the site's rendering folder to use as the clone
   source. Use the SiteHeader rendering created by T001:  
   `/sitecore/layout/Renderings/Project/harness-engineering/SiteHeader`  
   (Any other Json Rendering in the same folder is equally acceptable as the source.)

3. Right-click the source rendering item and choose **Scripts > Clone Rendering**.

4. The Clone Rendering dialog opens. Set the following values:

   | Dialog field | Value |
   |---|---|
   | **New rendering name** | `SiteFooter` |
   | **Rendering destination** | `/sitecore/layout/Renderings/Project/harness-engineering` |
   | **Datasource template** | **Create Copy** ← **must change from the default (Inheritance)** |
   | **Datasource template destination** | `/sitecore/templates/Project/harness-engineering` |
   | **Rendering parameters** | **Create Copy** ← **must change from the default (Inheritance)** |

   > **Important:** Both the **Datasource template** and **Rendering parameters** options
   > default to **Inheritance**. You **must** change both to **Create Copy**. Leaving either
   > on Inheritance causes the new rendering to share its template with the source rendering,
   > which creates field conflicts that are difficult to debug.

5. Click **Proceed**.

6. Confirm that the script reports success and that two new items have been created:
   - Rendering: `/sitecore/layout/Renderings/Project/harness-engineering/SiteFooter`
   - Template: `/sitecore/templates/Project/harness-engineering/SiteFooter`

## Section 2 — Configure Generated Items

The Clone Rendering script pre-populates the new items with defaults and fields copied from
the source rendering (`SiteHeader`). The steps below update those items with the correct values
for the `SiteFooter` component.

### 2.1 — Update the Rendering Item

**Item path:**
`/sitecore/layout/Renderings/Project/harness-engineering/SiteFooter`

**Steps:**

1. In Content Editor, navigate to  
   `/sitecore/layout/Renderings/Project/harness-engineering/SiteFooter`.

2. Set or verify the following field values:

   | Field | Required Value |
   |---|---|
   | **Component Name** | `SiteFooter` |
   | **Data Source Template** | `/sitecore/templates/Project/harness-engineering/SiteFooter` |
   | **Data Source Location** | `query:$site/*[@@name='Data']/*[@@templatename='SiteFooter']` ¹ |

   > ¹ **Query note:** `query:$site/*[@@name='Data']/*[@@templatename='SiteFooter']` uses the
   > SXA `$site` token and returns all `SiteFooter`-templated items in the site's Data folder
   > as selectable datasource choices in the component picker. Once the `SiteFooter` template
   > has been created and its GUID is known, replace `@@templatename='SiteFooter'` with
   > `@@templateid='{GUID}'` — `@@templateid` is the production-safe alternative because
   > template display names are not globally unique.

   > **Critical:** The `Component Name` field value must be exactly `SiteFooter` — this is
   > case-sensitive and must match the key registered in the Sitecore component map. A mismatch
   > causes the rendering to display blank on the page.

3. Remove any rendering parameter fields or other field clones that were copied from the source
   rendering but are not required by `SiteFooter`. The rendering item itself should contain only
   the standard Json Rendering fields.

4. Save the item (`Ctrl+S`).

---

### 2.2 — Update the Datasource Template

**Template path:**
`/sitecore/templates/Project/harness-engineering/SiteFooter`

The Clone Rendering script copied the field structure of the source rendering's datasource
template. Remove all cloned fields and replace them with the fields required by the
`SiteFooter` component, exactly as defined in `footerTypes.ts`.

**Steps:**

1. In Content Editor, navigate to  
   `/sitecore/templates/Project/harness-engineering/SiteFooter`.

2. Click **Builder** in the top ribbon.

3. Delete all field sections and fields that were cloned from the source rendering's template.
   The final template should contain only a single section and the six fields listed below.

4. Create a template section named **`Footer Content`**.

5. Inside the `Footer Content` section, add the following fields in order:

   | Field Name | Field Type | Notes |
   |---|---|---|
   | `Logo` | Image | Authored logo image; the rendering links this to the home page. |
   | `NavigationLinks` | Multilist | Set Source (see step 6). Each selected item must be of template `FooterNavigationLink`. |
   | `FacebookLink` | General Link | Facebook social URL. Leave empty to suppress the Facebook link. |
   | `TwitterLink` | General Link | X (Twitter) social URL. Leave empty to suppress the Twitter link. |
   | `LinkedInLink` | General Link | LinkedIn social URL. Leave empty to suppress the LinkedIn link. |
   | `CopyrightText` | Single-Line Text | Full copyright string, rendered as-is. |

   > **Field names are exact** — they must match the TypeScript field names in
   > `footerTypes.ts` character-for-character (case included). Mismatches cause the component
   > to receive `undefined` field values and render nothing.

6. Set the **Source** field on the `NavigationLinks` Multilist field to:

   ```
   query:$site/Data/#Footer Navigation Links#/*[@@templatename='FooterNavigationLink']
   ```

   > **Space escaping:** The folder name `Footer Navigation Links` contains spaces. The
   > segments must be wrapped in `#` delimiters (`#Footer Navigation Links#`) to prevent
   > the Sitecore XPath query parser from failing silently.
   >
   > **Query note:** This returns `FooterNavigationLink`-templated items from the
   > `Footer Navigation Links` folder under the current site's Data folder as the selectable
   > link options. Once the `FooterNavigationLink` template GUID is known (from the Pre-Requisite
   > step), replace `@@templatename='FooterNavigationLink'` with `@@templateid='{GUID}'`.

7. Save the template (`Ctrl+S`).

## Section 6 — Footer Partial Design

Create the "Footer" Partial Design and configure it to place the `SiteFooter` rendering in the
`headless-footer` placeholder.

> **UI method:** Partial Designs must be created through **Sitecore Pages** only.
> Do not use Content Editor insert options to create Partial Design items — this is not a
> supported or reliable method in XM Cloud SXA.

**Target item path (created by Pages):**
`/sitecore/content/harness-engineering/harness-engineering/Presentation/Partial Designs/Footer`

**Steps:**

1. Open **Sitecore Pages** and select the `harness-engineering` site.

2. In the left panel, navigate to the **Partial Designs** section
   (typically under **Site Settings > Partial Designs** or the design management panel).

3. Click **Create** (or the `+` button) to create a new Partial Design.  
   Enter the name: `Footer`. Confirm creation.

4. The new `Footer` Partial Design opens in the layout editor.

5. Locate the **`headless-footer`** placeholder in the layout canvas.

   > **Placeholder key check:** The placeholder key `headless-footer` is defined in the
   > rendering host's `Layout.tsx`. The key used here must match exactly. The CMS cannot
   > verify this — confirm against the registered key in `Layout.tsx` if the rendering
   > does not appear.

6. Add the `SiteFooter` rendering to the `headless-footer` placeholder:
   - Click the `headless-footer` placeholder slot.
   - Use the **Add rendering** picker to locate and select `SiteFooter`
     (it appears under the **Footer** Available Renderings collection added in Section 4).

7. Assign the data source to the rendering:
   - With the `SiteFooter` rendering selected in the layout editor, open its **component
     properties** (or datasource picker).
   - Select the `Footer` data source item created in Section 5.3:  
     `/sitecore/content/harness-engineering/harness-engineering/Data/Footer`

8. Confirm that no other renderings or placeholders have been modified by this Partial Design.

9. Save and publish the `Footer` Partial Design.
