## 1. Create Rendering and Datasource Template (Accelerate Cookbook)

> Before executing this section, visit the [Sitecore Accelerate Cookbook recipe](https://developers.sitecore.com/learn/accelerate/xm-cloud/implementation/developer-experience/creating-new-components) and verify whether the steps listed here match the current published version. If they differ, follow the published recipe over the steps in this guide.

The Accelerate Cookbook uses the **Clone Rendering** SPE script to create both the JSON Rendering item and the datasource template in one operation. Follow these steps:

### Step 1.1 — Navigate to the source rendering

In Content Editor, navigate to:

```
/sitecore/layout/Renderings/Feature/JSS Experience Accelerator/Page Content/Promo
```

This is the OOTB Promo rendering, used as the clone source because the Accordion has a datasource item.

### Step 1.2 — Run the Clone Rendering script

1. Right-click the **Promo** item.
2. Select **Scripts** → **Clone Rendering**.
3. In the dialog that appears:
   - **New rendering name:** `Accordion`
   - **Add to module:** select the `harness-engineering` project-layer module (or the appropriate module that targets `/sitecore/layout/Renderings/Project/harness-engineering`)
   - **Parameters tab:** change the option to **Create Copy** (not Inheritance).
   - **Datasource tab:** change the option to **Create Copy** (not Inheritance).

> **Critical:** Both the Parameters and Datasource options must be set to **Create Copy**. Leaving either on Inheritance shares templates with the Promo source rendering and causes field conflicts that are difficult to diagnose.

4. Click **Proceed**.

The script creates:
- A JSON Rendering item at `/sitecore/layout/Renderings/Project/harness-engineering/Accordion`

### Step 1.3 — Note GUIDs

- **Accordion rendering GUID** (from the rendering item's `__Item ID` field)
- **Accordion template GUID** (from the template item's `__Item ID` field)

## 2. Configure Generated Items

Update the rendering item and datasource template to match the Accordion component's actual requirements. The Clone Rendering script pre-populates these from the Promo source — the steps below correct them.

### 2.1 Update the Rendering Item

**Item path:** `/sitecore/layout/Renderings/Project/harness-engineering/Accordion`

**Tool:** `sitecore_update_item_fields`

Set or verify the following field values:

| Field | Required Value |
|-------|----------------|
| `Component Name` | `Accordion` |
| `Datasource Template` | `/sitecore/templates/Project/harness-engineering/Accordion` |
| `Datasource Location` | `query:$site/Data/Accordion/*[@@templatename='Accordion']` *(see note below)* |

> **`Component Name` is critical.** The value `Accordion` must match exactly the key used in `.sitecore/component-map.client.ts` (`['Accordion', { ...Accordion }]`). A mismatch causes the component to render blank.

> **`Datasource Location` note:** The query `query:$site/Data/Accordion/*[@@templatename='Accordion']` returns all items of template `Accordion` under the site's `Data/Accordion` folder as selectable datasource choices. The `$site` token resolves to the current site's content root and is required — never use an absolute path here. Replace `@@templatename='Accordion'` with `@@templateid='{GUID}'` (using the Accordion template GUID from Step 1.3) after the template has been created, since template names are not globally unique.

### 2.2 Update the Datasource Template

**Template path:** `/sitecore/templates/Project/harness-engineering/Accordion`

The Clone Rendering script creates this template with Promo-sourced fields. Remove all Promo-inherited fields and replace with the Accordion-specific fields below.

**Tool:** `sitecore_update_item_fields` (on the template's `__Standard Values` item, once fields are in place) or use the template field editor.

**Section name:** `Data`

**Required fields — remove any Promo fields, then add:**

| Field Name | Field Type | Source / Notes |
|------------|------------|----------------|
| `Items` | `Treelist` | Source: `query:./*[@@templatename='AccordionItem']` — returns child AccordionItem items of the datasource item as selectable choices. Replace `@@templatename='AccordionItem'` with `@@templateid='{AccordionItem-GUID}'` (GUID from Step P1) after creation. |
| `InitiallyExpandedItem` | `Single-Line Text` | Item ID of the AccordionItem that should be open on first render; leave empty for none open. |
| `HeadingLevel` | `Single-Line Text` | Valid values: `h2`, `h3`, `h4`. Default: leave empty (component defaults to `h3`). |
| `Variant` | `Single-Line Text` | Reserved for future presentation variants. Leave empty (component defaults to WKND base treatment). |

> **Insert Options:** Set `__Masters` on the Accordion template's `__Standard Values` item to allow `AccordionItem` as an insert option. This enables authors to create child AccordionItem items directly from the Accordion datasource item in Content Editor. Use `sitecore_sxa_set_insert_options` with the `AccordionItem` template GUID.

## 7. Add Rendering to Home Page

Add the Accordion rendering to the home page's `__Final Renderings` field so it appears at the bottom of `headless-main`, immediately before the footer.

**Target page:** `/sitecore/content/harness-engineering/harness-engineering/Home`

**Placeholder:** `headless-main`

### Step 7.1 — Read the current `__Final Renderings` value

Use a GraphQL query via the `sitecore-management` MCP server to retrieve the current `__Final Renderings` field value on the Home page item. Identify all existing `<r>` elements and note the highest `DynamicPlaceholderId` value present (call it `{MAX_ID}`).

### Step 7.2 — Construct the new `<r>` element

Build the new rendering entry using the following attribute values:

| Attribute | Value |
|-----------|-------|
| `uid` | Generate a new GUID (unique per rendering instance) |
| `p:after` | `"*[1=2]"` |
| `s:id` | GUID of the Accordion rendering item (from Step 1.3) |
| `s:ds` | GUID of the `Home-Accordion` datasource item (from Step 6.2) — **no curly braces** |
| `s:ph` | `headless-main` |
| `s:par` | `GridParameters=%7B7465D855-992E-4DC2-9855-A03250DFA74B%7D&amp;FieldNames&amp;Styles&amp;RenderingIdentifier&amp;CSSStyles&amp;DynamicPlaceholderId={MAX_ID+1}` |

**Example `<r>` element (replace placeholders with actual GUIDs):**
```xml
<r uid="{NEW-GUID}" p:after="*[1=2]" s:ds="{home-accordion-guid}" s:id="{accordion-rendering-guid}" s:par="GridParameters=%7B7465D855-992E-4DC2-9855-A03250DFA74B%7D&amp;FieldNames&amp;Styles&amp;RenderingIdentifier&amp;CSSStyles&amp;DynamicPlaceholderId=5" s:ph="headless-main" />
```

*(Replace `DynamicPlaceholderId=5` with `{MAX_ID+1}` based on what was found in Step 7.1.)*

### Step 7.3 — Update the field

Append the new `<r>` element inside the `<d id="{FE5D7FDF-89C0-4D99-9AA3-B5FBD009C9F3}">` device block of the existing XML, then update the field:

**Tool:** `sitecore_update_item_fields`

| Parameter | Value |
|-----------|-------|
| Item ID | GUID of the Home page item |
| Field | `__Final Renderings` |
| Value | Complete updated XML string |

> **If `__Final Renderings` is currently empty**, initialise with the full wrapper:
> ```xml
> <r xmlns:p="p" xmlns:s="s" p:p="1"><d id="{FE5D7FDF-89C0-4D99-9AA3-B5FBD009C9F3}"><r uid="{NEW-GUID}" p:before="*" s:ds="{home-accordion-guid}" s:id="{accordion-rendering-guid}" s:par="GridParameters=%7B7465D855-992E-4DC2-9855-A03250DFA74B%7D&amp;FieldNames&amp;Styles&amp;RenderingIdentifier&amp;CSSStyles&amp;DynamicPlaceholderId=1" s:ph="headless-main" /></d></r>
