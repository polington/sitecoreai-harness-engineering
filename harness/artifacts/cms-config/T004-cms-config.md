## 0. Pre-Requisites — Supporting Template and Overlay Opacity Option Items

   `/sitecore/templates/Project/harness-engineering/`

2. Right-click the `harness-engineering` folder and insert a new **Template** item named
   `OverlayOpacityOption`.

3. On the template, open the template builder. Create a template section named `Data`.

4. Add the following field to the `Data` section:

   | Field Name | Field Type |
   |------------|------------|
   | `Value` | Single-Line Text |

5. Save the template.

The OverlayOpacityOption template path is:
`/sitecore/templates/Project/harness-engineering/OverlayOpacityOption`

### 0.2 Create the HeroBanner Data Folder

1. Navigate to the site's Data folder:
   `/sitecore/content/harness-engineering/harness-engineering/Data/`

2. Right-click the `Data` folder and insert a new **Folder** item named `HeroBanner`.

   **Path after creation:**
   `/sitecore/content/harness-engineering/harness-engineering/Data/HeroBanner`

## 2. Configure Generated Items

Update the rendering item and datasource template that the Clone Rendering script
created. The script copies fields from the source rendering — the steps below correct
them for the HeroBanner component.

### 2.1 Update the Rendering Item

**Item path:**
`/sitecore/layout/Renderings/Project/harness-engineering/HeroBanner`

Set or verify the following field values:

| Field | Required Value | Notes |
|-------|----------------|-------|
| Component Name | `HeroBanner` | Must exactly match the component map key. A mismatch causes the component to render blank. |
| Data Source Template | `/sitecore/templates/Project/harness-engineering/HeroBanner` | Full path to the HeroBanner datasource template (section 2.2). |
| Data Source Location | `query:$site/*[@@name='Data']/HeroBanner/*[@@templatename='HeroBanner']` | Returns all items based on the `HeroBanner` template inside the `HeroBanner` subfolder of the site's `Data` folder. ⚠️ Once the HeroBanner datasource template has been created, replace `@@templatename='HeroBanner'` with `@@templateid='{GUID}'` using the template's actual item GUID — `@@templateid` is the production-safe form and avoids ambiguity with identically named templates. |
| Rendering Type | `JavaScript` | Should already be set correctly by the script; verify. |

> **Critical:** The `Component Name` field value must be exactly `HeroBanner` — this is
> the key registered in `.sitecore/component-map.ts`. Any capitalisation or spelling
> difference will cause the rendering to display blank in the browser.

### 2.2 Update the Datasource Template

**Template path:**
`/sitecore/templates/Project/harness-engineering/HeroBanner`

The script clones fields from the source rendering's datasource template. Remove all
cloned fields that are not listed below, then add or rename fields to match the
implementation exactly.

**Steps:**

1. In Content Editor, navigate to:
   `/sitecore/templates/Project/harness-engineering/HeroBanner`

2. Click **Builder** in the top ribbon.

3. Delete all field sections and fields that were cloned from the source rendering's
   template. The final template should contain only a single section and the five fields
   listed below.

4. Create a template section named **`Hero Banner Content`**.

5. Inside the `Hero Banner Content` section, add the following fields in order:

   | Field Name | Field Type | Notes |
   |------------|------------|-------|
   | `Heading` | Single-Line Text | Hero heading text, rendered as an `<h1>` element. |
   | `Subheading` | Single-Line Text | Supporting text below the heading, rendered as a `<p>` element. |
   | `BackgroundImage` | Image | Full-width background image with `object-fit: cover`. Author sets alt text via the image field's alt property. |
   | `CTALink` | General Link | Optional call-to-action link rendered as a styled button. Leave empty to suppress the CTA. |
   | `OverlayOpacity` | Droplink | Controls the opacity of the dark overlay scrim. Set Source (see step 6). |

   > **Field names are exact** — they must match the TypeScript field names in
   > `heroBannerTypes.ts` character-for-character (case included). Mismatches cause the
   > component to receive `undefined` field values and render nothing.

6. Set the **Source** field on the `OverlayOpacity` Droplink field to:

   ```
   /sitecore/content/harness-engineering/harness-engineering/Data/HeroBanner/Overlay Opacity Options
   ```

   > This displays all children of the Overlay Opacity Options folder (created in
   > section 0.4) as selectable values in the Droplink dropdown.

7. Configure **Standard Values** for the HeroBanner template:

   a. With the HeroBanner template selected, click **Options > Standard Values** in the
      ribbon (or right-click the template and choose **Insert Standard Values** if
      standard values do not yet exist).

   b. On the `__Standard Values` item, set the `OverlayOpacity` field to the **`40`**
      option item. This gives new HeroBanner items a default overlay opacity of 40%,
      making the hero immediately usable after authoring (within the 40–50% range
      specified by the design note).

   c. Save the standard values item.

8. Save the template (`Ctrl+S`).

**Base templates:** Retain `Standard template` as the base. Remove any source-rendering-
specific base templates if present.

> **Runtime field shape note (R3 risk):** The `OverlayOpacity` field is a Droplink. The
> exact shape of the field value delivered to the rendering host by the Content SDK depends
> on how Sitecore serialises the selected Droplink item. The component expects
> `fields.OverlayOpacity.value` to be a parseable numeric string (e.g. `"40"`). If the
> Content SDK delivers a complex object instead, the component's `parseOverlayOpacity`
> function falls back to the default 40% opacity. After completing CMS setup, verify the
> runtime field shape by rendering the hero banner in Sitecore Pages and inspecting the
> layout data. If the Droplink value is not delivered as a simple string, consider
> changing the field type to **Number** or **Single-Line Text** and replacing the Droplink
> option items with editorial guidance on acceptable values (30–80).
