## 1. Create Rendering and Datasource Template

> **Before executing this section**, visit the [Sitecore Accelerate Cookbook recipe](https://developers.sitecore.com/learn/accelerate/xm-cloud/implementation/developer-experience/creating-new-components) and verify whether the steps listed here match the current published version. If they differ, follow the published recipe over the steps in this guide.

The Carousel component requires a datasource item, so clone the OOTB **Promo** rendering. The Clone Rendering SPE script creates both the rendering definition item and a copy of the datasource template in a single operation.

### 1.1 Run the Clone Rendering Script

1. Open the **Sitecore Content Editor**.
2. Navigate to:
   `/sitecore/layout/Renderings/Feature/JSS Experience Accelerator/Page Content/Promo`
3. Right-click the `Promo` item → **Scripts** → **Clone Rendering**.
4. In the dialog, set the following values:

   | Field | Value |
   |-------|-------|
   | **New rendering name** | `Carousel` |
   | **Add to module** | `rea-harness-engineering` (your project layer module) |
   | **Parameters** tab → option | **Create Copy** — do NOT leave this on Inheritance |
   | **Datasource** tab → option | **Create Copy** — do NOT leave this on Inheritance |

   > **Critical:** Both the Parameters and Datasource options default to **Inheritance**. You must change both to **Create Copy**. Leaving either on Inheritance causes the new component to share its datasource template with the Promo rendering, leading to field conflicts.

5. Click **Proceed**.

The script creates the following items:
- Rendering item: `/sitecore/layout/Renderings/Project/harness-engineering/Carousel`
- Datasource template: `/sitecore/templates/Project/harness-engineering/Carousel`
- Standard Values item for the datasource template

Proceed to section 2 to configure the created items. Proceed to section 3 to create the Carousel Panel template (which the datasource template will reference).

## 8. Add Rendering to Page

Add the Carousel rendering to the Home page layout so it appears in the `headless-main` placeholder just before the footer.

**Target page:** `/sitecore/content/harness-engineering/harness-engineering/Home`  
**Placeholder:** `headless-main`  
**Position:** just before the footer rendering (use `p:after="*[1=2]"` to append; adjust position by reading existing renderings and inserting at the correct ordinal)

### Step 1 — Read the Current `__Final Renderings`

Query the Home page item's `__Final Renderings` field via the `sitecore-management` MCP server:

```graphql
query {
  item(path: "/sitecore/content/harness-engineering/harness-engineering/Home", language: "en") {
    fields(ownFields: false) {
      name
      value
    }
  }
}
```

Filter the response for the field named `__Final Renderings`. Note:
- The current XML structure and all `<r>` elements.
- The `DynamicPlaceholderId` values of all existing renderings.
- The maximum `DynamicPlaceholderId` value (call it `M`). The new Carousel rendering will use `DynamicPlaceholderId={M+1}`.
- The GUIDs of any existing `headless-main` renderings — the Carousel should appear after all existing `headless-main` renderings except the footer.

### Step 2 — Collect Required GUIDs

Before writing the updated XML, collect:

| Value | Source |
|-------|--------|
| `{RENDERING-GUID}` | GUID of `/sitecore/layout/Renderings/Project/harness-engineering/Carousel` — read via `sitecore_get_item` |
| `{DATASOURCE-GUID}` | GUID of `/sitecore/content/harness-engineering/harness-engineering/Home/Data/Carousel` — read via `sitecore_get_item` |
| `{NEW-UID}` | Generate a new random GUID for this rendering instance |
| `N` | `M + 1` where `M` is the current maximum `DynamicPlaceholderId` |

### Step 3 — Append the Carousel `<r>` Element

Append the following `<r>` element inside the `<d id="{FE5D7FDF-89C0-4D99-9AA3-B5FBD009C9F3}">` device block (the default SXA headless device block). Position it so it appears after the last non-footer `headless-main` rendering using an appropriate `p:before` or `p:after` value.

```xml
<r uid="{NEW-UID}" p:after="*[1=2]" s:ds="{DATASOURCE-GUID}" s:id="{RENDERING-GUID}" s:par="GridParameters=%7B7465D855-992E-4DC2-9855-A03250DFA74B%7D&amp;FieldNames&amp;Styles&amp;RenderingIdentifier&amp;CSSStyles&amp;DynamicPlaceholderId={N}" s:ph="headless-main" />
```

Replace all placeholder values with the actual GUIDs collected in Step 2. Remove curly braces from `s:ds` (the datasource GUID is written without braces in the `s:ds` attribute).

> If the Home page `__Final Renderings` is currently empty, initialize with the full wrapper:
> ```xml
> <r xmlns:p="p" xmlns:s="s" p:p="1"><d id="{FE5D7FDF-89C0-4D99-9AA3-B5FBD009C9F3}"><r uid="{NEW-UID}" p:before="*" s:ds="{DATASOURCE-GUID}" s:id="{RENDERING-GUID}" s:par="GridParameters=%7B7465D855-992E-4DC2-9855-A03250DFA74B%7D&amp;FieldNames&amp;Styles&amp;RenderingIdentifier&amp;CSSStyles&amp;DynamicPlaceholderId=1" s:ph="headless-main" /></d></r>
> ```

### Step 4 — Update the Field

Call `sitecore_update_item_fields` on the Home page item:

```json
{
  "itemId": "{HOME-PAGE-GUID}",
  "fields": [
    {
      "name": "__Final Renderings",
      "value": "{COMPLETE-UPDATED-XML-STRING}"
    }
  ],
  "language": "en"
}
```

Pass the entire updated XML string (not just the appended `<r>` element) as the field value.
