## 1. Create Rendering and Datasource Template

> Before executing this section, visit the [Sitecore Accelerate Cookbook recipe](https://developers.sitecore.com/learn/accelerate/xm-cloud/implementation/developer-experience/creating-new-components) and verify whether the steps listed here match the current published version. If they differ, follow the published recipe over the steps in this guide.

The following steps were sourced from the Accelerate Cookbook at generation time. The recipe prescribes using the **Clone Rendering** SPE script to create a new component from the Promo rendering (the recommended source for components that use datasource items).

**Steps:**

1. Open **Content Editor**.

2. Navigate to the Promo rendering source item. The Promo rendering in this project is at:  
   `/sitecore/layout/Renderings/Project/harness-engineering/PromoCardGrid`  
   *(The PromoCardGrid was itself cloned from the OOTB Promo. Use it as the source for this clone.)*

3. Right-click the `PromoCardGrid` rendering item and select **Scripts > Clone Rendering**.

4. In the Clone Rendering dialog:

   | Setting | Value |
   |---------|-------|
   | **New rendering name** | `Teaser` |
   | **Rendering destination** | `/sitecore/layout/Renderings/Project/harness-engineering` |
   | **Datasource template destination** | `/sitecore/templates/Project/harness-engineering` |
   | **Datasource option** | **Create Copy** *(not Inheritance)* |
   | **Parameters template option** | **Create Copy** *(not Inheritance)* |

   > **Critical:** Both **Datasource** and **Parameters template** options must be set to **Create Copy**. Leaving them on Inheritance causes the Teaser to share its datasource template with PromoCardGrid, resulting in field conflicts that are difficult to debug.

5. Click **Proceed**. The script creates:
   - A new rendering item at `/sitecore/layout/Renderings/Project/harness-engineering/Teaser`
   - A new datasource template at `/sitecore/templates/Project/harness-engineering/Teaser`
   - A new template folder at `/sitecore/templates/Project/harness-engineering/Teaser`

6. Note the GUID of the newly created `Teaser` rendering item — you will need it for the Placeholder Settings and Available Renderings updates in sections 4 and 5.

After completing these steps, proceed to section 2 to update the generated items with the correct field values for this component.

## 2. Configure Generated Items

Update the rendering item and datasource template that the Clone Rendering script created.

### 2.1 Update the Rendering Item

**Item path:** `/sitecore/layout/Renderings/Project/harness-engineering/Teaser`

Open the item in Content Editor and set or verify these field values:

| Field | Required Value | Notes |
|-------|----------------|-------|
| `componentName` | `Teaser` | Must exactly match the key registered in the component map. A mismatch causes a blank render. |
| `Datasource Template` | `/sitecore/templates/Project/harness-engineering/Teaser` | Path to the datasource template created by the clone script. |
| `Datasource Location` | `query:$site/*[@@name='Data']/*[@@templatename='Teaser']` | Returns Teaser datasource items from the site's Data folder. Replace `@@templatename` with `@@templateid='{GUID}'` after the Teaser template has been created (see note below). |
| `Open Properties after Add` | `0` | Suppresses the properties dialog on drag-and-drop placement. |
| `IsRenderingsWithDynamicPlaceholders` | `true` (set via `OtherProperties` field as `IsRenderingsWithDynamicPlaceholders=true`) | Consistent with the existing component pattern. |

> **Note on `@@templatename`:** Using `@@templatename='Teaser'` is acceptable while the template GUID is not yet known. After the Teaser template is created and its GUID is available, replace the query with `@@templateid='{GUID}'` — for example `query:$site/*[@@name='Data']/*[@@templateid='{your-guid-here}']`. Template display names are not globally unique; `@@templateid` is the production-safe form.

### 2.2 Update the Datasource Template

**Template path:** `/sitecore/templates/Project/harness-engineering/Teaser`

The Clone Rendering script copies the PromoCardGrid's datasource fields. Remove all cloned fields that do not belong to the Teaser, then add or rename fields to match the implementation exactly.

Open the template in Content Editor, select the **Builder** tab, and configure a single template section named `Data` with the following fields:

**Fields to add or rename:**

| Field Name | Field Type | Notes |
|------------|------------|-------|
| `Image` | Image | Primary teaser image. |
| `ImageDecorative` | Checkbox | When checked, the image is decorative; alt text is set to empty and the image is excluded from the accessibility tree. |
| `ImagePosition` | Droplist | Focal crop positioning. See Source value below. |
| `Pretitle` | Single-Line Text | Short contextual label above the title. |
| `Title` | Single-Line Text | Primary teaser title. |
| `TitleHeadingLevel` | Droplist | Heading level for the title element. See Source value below. |
| `Description` | Rich Text | Optional editorial description. |
| `PrimaryLink` | General Link | Optional destination link that makes the whole teaser navigable as a unit (only used when no Actions are configured). |
| `Variant` | Droplist | Presentation variant selection. See Source value below. |
| `TitleSourcing` | Checkbox | When checked, title is resolved from the LinkedItem instead of the direct Title field. |
| `DescriptionSourcing` | Checkbox | When checked, description is resolved from the LinkedItem instead of the direct Description field. |
| `ImageSourcing` | Checkbox | When checked, image is resolved from the LinkedItem instead of the direct Image field. |
| `LinkedItem` | Droptree | Optional linked content item. Used when TitleSourcing, DescriptionSourcing, or ImageSourcing is enabled. |
| `Actions` | Multilist | Zero or more TeaserAction child items providing labeled CTA links. See Source value below. |

**Droplist and Multilist Source field values:**

| Field | Source |
|-------|--------|
| `Variant` | `default\|featured\|hero\|card\|list\|slide\|secure` |
| `ImagePosition` | `imagetop\|imagebottom` |
| `TitleHeadingLevel` | `H2\|H3\|H4` |
| `Actions` | `query:$site/Data/Teaser/*[@@templatename='TeaserAction']` *(replace with `@@templateid` once GUID is known)* |

> **Note on the `Actions` Multilist Source:** The query `query:$site/Data/Teaser/*[@@templatename='TeaserAction']` returns TeaserAction items stored under the Teaser data folder as the selectable choices for the Actions field. Authors must create TeaserAction child items under the datasource item for this picker to show options. Ensure TeaserAction items are created under each Teaser datasource item (see section 6).

**Remove any fields** inherited from the PromoCardGrid clone (e.g., `Cards`, `Heading`, or any PromoCard-specific fields) that are not in the table above.

**Base templates:**  
Ensure the Teaser template inherits from:
- Standard template: `{1930BBEB-7805-471A-A3BE-4858AC7CF696}`
- `Headless SXA Datasource` or equivalent SXA base template if required by the project's SXA setup (check whether PromoCardGrid template's `__Base template` field includes such a template and mirror it).

## 6. Content Items

Create the initial content structure to allow end-to-end testing of the component with authored data.

### 6.1 Create the Teaser Data Folder

**Item path:** `/sitecore/content/harness-engineering/harness-engineering/Data/Teaser`

1. In Content Editor, navigate to `/sitecore/content/harness-engineering/harness-engineering/Data`.

2. Right-click the `Data` folder and select **Insert > Insert from Template**.

3. Select the **Common/Folder** template (or the site's standard data folder template). Name the folder `Teaser`.

4. Save.

### 6.2 Create a Teaser Datasource Item

**Item path:** `/sitecore/content/harness-engineering/harness-engineering/Data/Teaser/{name}`

> Create one datasource item per teaser instance the author wants to place. The example below creates a single validation item.

1. In Content Editor, navigate to `/sitecore/content/harness-engineering/harness-engineering/Data/Teaser`.

2. Right-click the `Teaser` folder and select **Insert > Insert from Template**.

3. Select the `Teaser` template (created in section 2.2). Name the item `Homepage Teaser`.

4. Populate initial field values for validation (all fields are optional; populate what is needed for initial testing):

   | Field | Initial Value |
   |-------|---------------|
   | `Title` | `Example Teaser Title` |
   | `Description` | `<p>Example teaser description for validation.</p>` |
   | `Image` | Select an image from `/sitecore/media library/Project/harness-engineering` |
   | `Variant` | `default` |
   | `TitleHeadingLevel` | `H2` |
   | All other fields | `(set by author or leave empty for initial testing)` |

5. Save the item.

### 6.3 Create TeaserAction Items Under the Datasource Item

Create one or more TeaserAction child items under the datasource item created in step 6.2. These are the items the `Actions` Multilist field will reference.

1. Right-click the `Homepage Teaser` item and select **Insert > Insert from Template**.

2. Select the `TeaserAction` template (created in the Pre-Requisite section). Name the item `Read More`.

3. Set the following fields:

   | Field | Value |
   |-------|-------|
   | `Label` | `Read More` |
   | `Link` | Select a destination URL or internal content item |

4. Save.

5. Repeat to create additional TeaserAction items as needed (e.g., `Subscribe`, `Learn More`).

> **Note:** TeaserAction items should be created as children of the Teaser datasource item. The `Actions` Multilist Source query (`query:$site/Data/Teaser/*[@@templatename='TeaserAction']`) returns items of type TeaserAction that are direct children of any item under `/Data/Teaser/`. If you need per-teaser action item sets, create the TeaserAction items as children of each specific Teaser datasource item and adjust the Multilist Source accordingly.
