## 2. Configure Generated Items

Update the rendering item and datasource template that the Clone Rendering script
created. The script copies fields from the Promo source — the steps below correct them
for the Header component.

### 2.1 Update the Rendering Item

**Item path:**
`/sitecore/layout/Renderings/Project/harness-engineering/Header`

Set or verify the following field values:

| Field | Required Value | Notes |
|-------|----------------|-------|
| Component Name | `Header` | Must exactly match the component map key. A mismatch causes the component to render blank. |
| Datasource Template | `/sitecore/templates/Project/harness-engineering/Header` | Full path to the Header datasource template (section 2.2). |
| Datasource Location | `query:$site/*[@@name='Data']/*[@@templatename='Header']` | Returns all items based on the `Header` template directly under the site's `Data` folder as selectable datasource choices. The picker shows each individual Header-template item — not a folder browser. The Header data source item created in section 5.3 will appear here. ⚠️ Once the Header datasource template has been created, replace `@@templatename='Header'` with `@@templateid='{GUID}'` using the template's actual item GUID — `@@templateid` is the production-safe form and avoids ambiguity with identically named templates. |
| Rendering Type | `JavaScript` | Should already be set correctly by the script; verify. |

> **Critical:** The `Component Name` field value must be exactly `Header` — this is the
> key registered in `.sitecore/component-map.ts`. Any capitalisation or spelling difference
> will cause the rendering to display blank in the browser.

### 2.2 Update the Datasource Template

**Template path:**
`/sitecore/templates/Project/harness-engineering/Header`

The script clones fields from the Promo datasource template. Remove all cloned fields
that are not listed below, then add or rename fields to match the implementation exactly.

**Required fields (template section: `Data`):**

| Field Name | Field Type | Notes |
|------------|------------|-------|
| `Logo` | Image | The site logo image, rendered via the JSS `<Image>` field primitive. |
| `NavigationLinks` | Multilist | Source query — see below. References NavigationLink items created in section 5.2. |

**Multilist field source for `NavigationLinks`:**

```
query:$site/Data/#Navigation Links#/*[@@templatename='NavigationLink']
```

> **Important — `$site`-relative query:** The `$site` token is resolved by the SXA
> `DataSourceSettingsProvider` to the content root of the current site. This means the
> query works regardless of tenant name or site collection path. Never replace `$site`
> with a hard-coded absolute path — doing so breaks the query on any environment that
> uses a different site collection name.

> **Important — XPath space escaping:** The `Navigation Links` folder name contains a
> space. Sitecore's XPath query parser requires that path segments containing spaces be
> wrapped in `#` delimiters. Without `#Navigation Links#`, the query silently returns zero
> items and the multilist field source will appear empty. Copy the query exactly as written
> above.

> **Important — `@@templatename` caveat:** The query uses `@@templatename='NavigationLink'`
> because the NavigationLink template GUID is not yet known at guide-generation time. Once
> the NavigationLink template has been created (section 0), replace `@@templatename='NavigationLink'`
> with `@@templateid='{GUID}'` using the template's actual item GUID. The `@@templateid`
> form is the production-safe alternative — display names are not globally unique and
> `@@templateid` avoids silent mismatches.

Delete any fields cloned from Promo that are not `Logo` or `NavigationLinks`.

**Base templates:** Retain `Standard template` as the base. Remove any Promo-specific
base templates if present.
